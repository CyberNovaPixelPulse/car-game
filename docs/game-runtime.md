# 房間與遊戲核心的交接

目前的賽車仍使用原有 C／SDL2／Emscripten 核心與五人房間。這次前置整理不更改遊戲規則，也不解除既有建置要求；坦克改版會在後續票逐步接入新核心。

`GameRuntime` 負責房間與核心之間的生命週期：

- 房間開始時把既有席位遮罩轉成參與者清單與種子，再啟動核心。
- 房主處理模擬；其他玩家只提交輸入。既有 50ms 發送間隔、房主權威及序號檢查維持不變。
- 輸入分為持續按住與待送出的單次操作，失焦、返回選單及重新開始時清除，避免把短按操作漏在網路發送間隔之間。
- 連線狀態更新交給核心，重連快照由核心還原；UI 只處理畫面與還原錯誤提示。
- 結算交給房間發布最後快照，房主離開仍結束房間，不增加房主移轉或額外遊戲伺服器。

`GameCore<View>` 是遊戲接入的 interface。核心接受參與者清單、種子與是否練習的啟動設定，提供輸入、步進、繪圖、可呈現狀態與快照還原。房間不需要知道 C 的記憶體位址或序列化方式；目前 `Engine` adapter 將啟動設定轉為舊的 C 遮罩，並保留既有快照格式。

UI 的三個通知接點是開始、房間更新及快照還原失敗。賽車圈數、排名、道具、倒數與結果判斷仍留在賽車呈現端，不進入通用 runtime。

這是移轉中的契約：目前輸入仍是舊賽車的數字按鍵遮罩，房間仍保留五席和 racing 階段。坦克票會以實際角色操作需求演進這些契約；新遊戲完全接入後，再於整合驗收移除無呼叫者的 C adapter、舊入口及過渡形式，避免先刪舊核心造成中途無法建置。

驗證只經已確認的瀏覽器端到端接點，沿用真實 PeerServer／WebRTC、鍵盤與畫面結果；不增加核心內部測試介面，也不直接注入車輛或賽局狀態。
