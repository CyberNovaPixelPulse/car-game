# 以 TypeScript 房主模擬與 Three.js 呈現同一台坦克

父規格 #11 取消 C 語言要求，並將產品由一人一車賽車改為三人共駕的 3D 坦克。此決策取代舊決策中「本作業要求 C 核心」的現行限制；最終 #27 已移除舊賽車入口、C／Wasm adapter 及必要建置。

使用 TypeScript 實作坦克權威狀態與規則，以 Three.js WebGL2 顯示戰場，沿用既有 GameCore／GameRuntime 的啟動、輸入、步進、快照與呈現介面。沒有增加專用遊戲伺服器或另造連線協定；Session() 仍以 PeerJS／WebRTC 傳輸，房主瀏覽器模擬並約每 50ms 傳送一致快照。

房主身分與乘員職位分離。核心按權威房間中的職位接受輸入，只有駕駛能控制車身；角色介面不能決定碰撞結果。車身位置、方向、速度、轉速及碰撞由同一個權威狀態驅動，而不是三個瀏覽器各算一台車。

視角是呈現限制：駕駛只顯示允許的儀表，不建立外部 canvas，也不以隱藏 DOM 暴露座標或地圖；砲手使用隨車身前方的 3D 主炮視角；裝填手顯示封閉 3D 車內並可切換機槍外景。後續主炮、裝填與機槍會延伸這份狀態，不把測試接點下移到內部函式。

現階段固定掩體的視覺與碰撞共用相同場地描述，防止看得見的石牆可以穿越。初始場景、車體與材質是可運作的 3D 接入，最終史料外觀與寫實細節由 #25／#26 驗收，不能以此視為最終美術完成。

代價：客端跟隨房主快照，網路延遲可能造成視覺步進，房主仍必須在線。正式遊玩需要支援 WebGL2 的桌面瀏覽器；初始化失敗顯示明確錯誤。三人測試沿用真實瀏覽器、WebRTC、鍵盤與畫面接點，沒有私人狀態注入。

參考：已安裝 Three.js 的 WebGLRenderer、MeshStandardMaterial 與 PerspectiveCamera 實作；官方來源 https://github.com/mrdoob/three.js 。


#15 將主炮的真實按鍵動作與持續按住的駕駛輸入分開。GameRuntime.action 對房主本地核心直接送出、對一般乘員立即經既有可靠有序 PeerJS 連線送出，每次動作一則訊息，不併入 OR 位元佇列。動作與 held input 共用同一個 epoch／遞增序號檢查，因此快速連點不會合併遺失，也不會在舊序號重播；權威核心仍以乘員職位判斷能否接受。GameCore 的 action 是可選延伸，舊 C adapter 與賽車輸入不需改成新的操作規則。

主炮水平相對車身轉動、俯仰獨立受限，兩軸轉速由同一個房主模擬時鐘衰減。視角、砲塔與砲管幾何讀取相同快照；砲手的朝向及角速度儀表是正式可見的操作回饋，沒有在駕駛介面埋入隱藏戰況。每次真實 keydown 才給一次推力，忽略 event.repeat，滑鼠沒有瞄準事件處理。

#16 將正常主炮工作循環放在權威武器規則模組。砲膛分為空膛、裝填、已裝填及退殼四個階段；裝填以持續按住的 R 推進，放開保留進度，射擊使用離散 FIRE 動作且只由砲手觸發。退殼完成前不能開始下一發。飛行彈、命中靶標及退殼時間均由同一模擬時鐘決定，Three.js 與車內工作區只呈現快照，不以動畫回呼決定射擊或裝好。後續彈種、卡彈、閃避會延伸這個工作循環，本階段沒有提前加入其規則。

#18 使用 GameStart.seed 初始化並在武器快照保存隨機序列。每發開始裝填時只抽一次 25% 故障，若中籤在 40% 進度卡住；成功後同發不再抽籤，退殼後下一發才可新增故障。卡彈保存綠區、指針方向、停針結果及同一模擬時鐘的一秒重試期限，放開 R 或斷線暫停不清除。裝填手的空白鍵送出離散 STOP_JAM=9，房主以自身指針與綠區判定；客端只呈現快照，不依動畫或鍵盤本地時間判定成功。固定種子測試只替換開始戰鬥的單一 Uint32 熵來源，房間代碼與乘員憑證仍使用真實隨機。

#19 的退殼命中與姿勢仍由房主規則判斷。C 是裝填手的持續 held bit32，不是按一下切換；蹲下或 `stunnedUntil` 尚未到期時，`loaderCanWork` 封鎖工作。彈殼命中只設定退殼截止時間加固定五秒的遊戲時鐘期限，不扣車體血量，不清除彈種、裝填或卡彈欄位；網路快照／重新按鍵不能縮短期限。聲音與視覺預警同時從同一個退殼快照呈現，畫面動畫不決定命中。後續機槍模式與解卡彈動作必須共用此工作條件及退殼風險。

低幀率不能使固定五秒暈眩變長。坦克核心保留每次完整 elapsed，以每步不超過 0.05 秒的子步推進物理、投射物及規則，而不是丟掉超過單步上限的時間。新局／本機開始時 Runtime 重設幀基準，大廳等候不補算進戰鬥；未來暫停必須停止這個共同時鐘並於恢復時校正幀基準，不能以呈現端倒數代替權威規則。

#21 以 `weapon.targets` 延伸兩類實際敵車，保留主炮與機槍的同一傷害接收契約。房主同一個完整 elapsed 小步時鐘推進敵車繞行、砲塔、瞄準預告、敵彈與共用 HP；呈現端逐幀同步敵車的位置與炮塔。敵人固定一次預告射線後發射真正移動的炮彈，車體／掩體最近交點決定傷害；不在預告時直接扣血，也不以動畫回呼命中。HP 歸零由權威快照提供全員一致的本次失敗，後續波次與回房流程由 #23 延伸。


#27 完成根目錄單一坦克入口，刪除未使用本機賽車 API、五席 mask 與 race 分支；網路開始傳送三席 participants，維持 tank-crew-v1 namespace 與既有 sessionStorage key。所有輸入按實際房主接收時刻先推進舊控制，再套用新狀態；記住暫停前狀態並且不回退到舊 rAF 時戳。可調規則集中 tank-settings，固定五秒暈眩不納入調參。美術採使用者明確接受的簡化外觀，素材來源、機械附著及角色資訊限制仍有效。
