### 失敗原因與處理

1. **瞄準固定延遲斷言**：原始trace在送出ArrowLeft後等120ms，兩次讀到同一個46.4°/s。這個觀察包含輸入傳輸、房主結算、snapshot及HUD繪製，不能等同核心已前進120ms。核心瞄準規則未被本次架構修改；內建瀏覽器證明正常煞停與反轉。`tank-aiming.spec.ts`改以1秒內每20ms讀取同一筆`0 < rate < 45`煞停樣本，保留後續負向上限與停止斷言；若直接跳成負速，煞停斷言仍會失敗。已用內建瀏覽器驗證這個觀察條件，未另開Chromium重跑該測試檔。
2. **全螢幕環境**：原始外部完整批次在`document.hasFocus()`失敗，尚未走到全螢幕按鈕。內建瀏覽器則在原始main與整合版均拒絕全螢幕請求，兩者均顯示可繼續遊玩的回退訊息。不能把兩種環境的失敗混成相同原因；成功全螢幕／原生Esc仍受環境限制而未認證。
3. **內建瀏覽器操作時序**：原生長按會將另一個原生按鍵排在後面；正式locator鍵盤介面可在長按R時送出可信Space。跨分頁操作會清除另一頁的held controls，因此改為砲手射擊後立即讓裝填手蹲下。重連後先等公開暫停提示消失，再核對彈種後裝填，避免凍結期間按鍵被忽略。這些均為驗證操作調整，未放寬遊戲規則。
4. **三波未完成的嘗試**：診斷、過長工具呼叫及原地維修耗盡增援空檔，造成自然受擊至HP0。失敗沒有算成通過；最終完整勝利另有三方證據。最後一發擊毀虎式後停在「正在退殼」是勝利凍結的結果，原臨時操作只等空膛而報逾時；原有正式waves測試本來就允許戰鬥結果可見作為完成條件，沒有修改這項條件。
