# 執行草案 v2：有限交付與低負載驗證

狀態：專案工作流程草案；技能檔不變。此流程補充技能的專案執行方式。

## 每輪交付

1. 開始時更新 `docs/agents/current-task.md`：範圍、交付物、預算、開始與截止時間。未另約定時，以30分鐘檢查點規劃；較長功能拆里程碑。
2. 第一條可試玩的正常流程完成即提供入口並進行審查。完整驗收獨立記錄，未完成時維持Draft與明確缺口。
3. 改動先跑 `npm test`。它只做便宜檢查與案例收集；應用程式變更另跑build。
4. 失敗先分類：正常玩家缺陷、測試假設／策略、工具／環境、未知。記錄證據、影響、新假設及下一個最小案例。
5. 同一問題最多兩輪有新假設的修正／驗證。仍未收斂就保存、交付現況；一般維護與測試工具擴張另列工作。
6. 截止前停止新增修補與測試，交付來源、入口、逐批結果、審查狀態與未解問題。完整綠燈不作為試玩或審查前置條件。

## 資源與測試

- 此Mac只開一個遊戲畫面供手動觀察。現有自動E2E會建立多個3D場景，設定層直接阻止在macOS執行；案例收集允許。
- 三人驗證保留正常瀏覽器／鍵盤→真實PeerJS/WebRTC→房主權威→可見結果接點。優先由不同裝置操作；裝置未備即列待驗，不新增單人作弊模式或私有狀態注入。
- 既有自動E2E僅供資源已確認的其他驗證主機，結果須標示同機多context／多Browser，不能稱為多裝置驗證。`TANK_E2E_RESOURCE_READY=1`是顯式入口，並不證明主機資源或授權。
- 針對案例須指定檔案、grep與global timeout，上限10分鐘。完整回歸需另外設 `TANK_FULL_REGRESSION=1`，上限75分鐘；先列理由、影響範圍、成本，取得本輪明確排程後才執行。
- 可選錄影預設關閉；只在證據需要時短時間開啟。真正消費影片的案例保留required錄影；在本機也受多場景限制。
- 同來源且未受修改影響的證據可沿用，逐批描述。錄影／測試負載下的失敗保留環境疑慮，未知原因維持未知。

## 檢查與證據

- `npm test`／`npm run verify:fast`：規則自檢、既有型別檢查、Playwright案例收集；不啟動瀏覽器。CI另外執行既有build。
- 每次快速檢查建立獨立 `output/qa/<run-id>/`，以原子方式更新 `output/qa/latest.json`。`npm run verify:status`讀取最新報告；已退出程序的running紀錄顯示interrupted。
- 手動或資源主機E2E每次嘗試使用全新證據／log／JSON目錄。重複案例改用獨立命令目錄，避免共用手動PNG別名；E2E入口也建立唯一run、接管證據／JSON／test-results，拒絕舊輸出路徑覆寫、UI無限等待、平行worker及repeat-each；後續新增capture採用 `testInfo.outputPath()`。
- 兩輪上限與假設分類需要判斷，由執行／審查把關；本輪不新增自動除錯排程器。global timeout與本機多場景禁用由設定檢查。
- 最新任務只維護一份狀態；歷史原始紀錄留在獨立run目錄。先讀摘要，有新線索才展開trace。

## 後續與限制

目前CI只提供輕量防護，不自動跑遊戲E2E；分散式實機驗證尚無自動runner。本輪不建造該系統。此限制不改動功能規格或解除未驗證項目。
