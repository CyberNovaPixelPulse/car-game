# 裝填手車內維修

Tab 依序循環裝填、機槍、維修，再回到裝填。維修重用準備階段載入、編譯及首畫完成的封閉車內 renderer，中央面板顯示工作條件與當前原因。沒有外部戰場視野；原有退殼預警、C 蹲下、固定五秒暈眩與武器狀態仍可見。

按住 R 時，房主在每次完整 elapsed 的物理子步先處理敵彈傷害與車身移動，再判斷維修。存活、未蹲下／暈眩、速度與轉速絕對值均不超過 0.01，且受擊等待已結束，才每秒回復 2 HP，最高 100。沒有材料限制；滿血暫停工作。HP 歸零在同一步立即失敗，不能由維修復活。HUD 的小數血量顯示到一位，規則保留連續精度。

每次敵彈實際扣血都令禁修期限至少延至該次命中加三秒；新的命中重新計時。放開 R、移動／轉向、蹲下／暈眩或切換工作都停止回血。三模式切換保留同一發彈種、進度、卡彈、退殼、機槍熱度與冷卻；空白鍵仍由目前模式決定用途，維修目前不會操作卡彈或機槍。

## 權威狀態與後續校準接點

`TankState.version = 2`，新增獨立 `repair`：

- `status`：inactive、destroyed、stunned、crouching、moving、waiting、full、ready、repairing，由房主決定當前工作原因。
- `blockedUntil`：共用遊戲時鐘上的最晚禁修期限；後續校準失敗應以 `Math.max` 延長此欄位，避免與受擊等待相加或互相清除。
- `activeSeconds`：實際有效維修的累積工作時間；滿血與受阻不推進，供後續校準間隔使用。

`createRepairState`、`stepRepair`、`validRepair` 位於 `web/tank-repair.ts`。校準本身由 #40 接上；本切片不提前建立轉針、隨機區域、獎勵或失敗規則。新增規則值集中於 `REPAIR_RULES`。

`repair-status` 是中央面板的可見工作狀態；`loader-mode`、`tank-health`、`ejection-warning`、`loader-status`、`stun-remaining` 繼續使用原有公開 UI。維修與主炮解卡彈使用各自狀態，避免共用空白鍵互相改寫。

缺員時沿用 Runtime 的遊戲時鐘凍結：HP、有效工作時間及禁修期限都保留，不補算現實等待。恢復會清除持續輸入，裝填手需重新按 R。模式與受擊等待跨波保留，回同房新開一局則由初始狀態全部重設。取消準備、換職、離開及返回依原有資源所有權失效與釋放，共用車內 renderer 不增加第二份 GPU 資源。

## 驗證

`tests/tank-repair.spec.ts` 從真實三人房間、鍵盤與敵彈驗證三模式、工作互斥、實際受損、三秒等待、每秒 2 HP、100 上限與三方一致。`tests/tank-repair-lifecycle.spec.ts` 驗證移動／原地轉向／蹲下／放開／切換中斷、真實缺員暫停與原職位重連、卡彈保留、維修退殼避險／五秒暈眩、失敗不復活與同房換職新局。測試不注入 HP、位置、工作進度或內部規則。
